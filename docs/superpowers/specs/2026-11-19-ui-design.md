# controlk: picker styles and prefix suggestions

Status: approved by the owner, 2026-11-19.

## Intent

controlk is modelled on Qt Creator's locator, but today it only borrows the prefixes: the picker
is a standard Telescope float. The owner wants a second look that feels like Qt Creator, where
the locator is a small input in the bottom-left corner and the list of candidates appears above
it as you type. They also want help with prefixes as they type, so a user does not have to
remember them: `?` shows them at once, and a partly typed prefix suggests the ones it could
become.

The current look stays, for users who like Telescope as it is. Owner, 2026-11-19: "not only 2,
telescope styles + cutie". Each of Telescope's layouts and themes is a style of its own, next to
cutie, all chosen with one option.

## Goals

- One `style` option chooses among the **Telescope styles** (every Telescope layout and theme,
  plus `default`, today's picker) and **cutie** (Qt Creator).
- The cutie style: a prompt in the bottom-left corner, above the status line; the results list
  above the prompt; a preview to the right. The list and the preview appear only once something
  is typed.
- `?` on its own, with no space, shows the prefix list.
- A partly typed prefix lists the prefixes it could become, above the usual results.

## Non-goals

- A permanent locator box that stays on screen. The cutie style opens on Ctrl+K and closes when
  an item is picked or on Esc, like any Telescope picker. A permanent box would be a window kept
  alive outside Telescope, which is a different project.
- Prefix icons. They are TASKS.md T14, built later on top of this.
- Ranking workspace symbols by prefix match (`c W` putting `Widget` before `Swing`). clangd's
  order is kept. It is a separate wish.
- Reading any plugin's configuration, or the user's Neovim config, to size cutie. A user may
  have Neo-tree, nvim-tree, another file tree, or none. Owner, 2026-11-19: "don't look into a
  specific plugin configuration". The width comes from controlk's own option, or from what the
  Neovim API reports about the windows on screen (see Cutie style).
- The Snacks adapter (T11).

## Anti-goals

These would make the work a failure even if it technically works:

- The cutie windows cover the status line or the command line. The owner wants that information
  visible at all times.
- A user who sets nothing sees any change from today's picker, apart from the new prefix
  suggestion rows.
- A prefix suggestion hides results. Typing `c` must still find `CMakeLists.txt`, below the
  suggestion rows.
- Telescope code outside `picker.lua`, or a source that knows which style is active.

## Constraints

- Only `picker.lua` may require `telescope.*`. A cutie layout function can live in a second
  adapter file only if CLAUDE.md is updated to say so; the builder should prefer `picker.lua`.
- Every change works on the four CI pairs: Neovim 0.10.4 with Telescope v0.2.0 and v0.1.9,
  0.11.7 with v0.2.2, and 0.12.6 with master at `1e1bab7`.
- Facts checked on those Telescope versions (v0.1.9, v0.2.0, `1e1bab7`):
  - `layout_strategies` has `horizontal`, `vertical`, `center`, `cursor`, `flex`,
    `bottom_pane` and `current_buffer`; `telescope.themes` has `get_dropdown`, `get_ivy` and
    `get_cursor`.
  - A picker accepts `create_layout` (full control of its windows) and `get_window_options`.
  - Telescope's default layout already leaves the status line and the command line free: it
    takes `vim.o.lines - vim.o.cmdheight`, minus one line when `laststatus` is not 0.
- Neovim 0.10 added `hide` to floating window configs (`news-0.10.txt`), so a float can be
  hidden and shown again without being closed. 0.10.4 is the oldest supported version.
- Telescope draws each window's border as its own window. Hiding a list or preview means hiding
  its border window too.

## Approaches

For the cutie style:

1. **A custom Telescope layout. Chosen by the owner, 2026-11-19.** The cutie style computes where
   the prompt, results and preview go, and passes that to Telescope, which still creates the
   windows, sorts and previews. The list and the preview are hidden while the prompt is empty,
   using the `hide` field. Everything else, the sorter, the previewer and the sources, works as
   it does today. The risk is the hiding: Telescope does not expect its windows to disappear.
2. **Only Telescope's built-in layouts**, such as `bottom_pane`. Little code, but it cannot put
   the prompt in the corner at a fixed width, or hide the list while the prompt is empty.
   Rejected: it misses what makes the style.
3. **Our own windows, no Telescope.** Full control, but filtering, preview and keys would be
   rewritten. Kept as the fallback the owner named: "if not, we try our own". The builder
   switches to it only if approach 1 cannot be made to pass on all four pairs, and says so
   before starting.

For the Telescope styles there is one sensible way: pass Telescope's own options through. Owner's
words: "keep as it is, don't make it visible/invisible", "it can also choose from the Telescope
layouts", and "not only 2, telescope styles + cutie".

For prefix suggestions, the owner chose **suggestions on top of the usual results** over
suggestions only, 2026-11-19: "I'm fine with showing the prefixes than showing the files that
matches the start of the search".

## Design

### Configuration

New options, with these defaults:

```lua
-- "default": Telescope's own defaults, as configured in telescope.setup (today's picker).
-- A Telescope layout: "horizontal", "vertical", "flex", "center", "bottom_pane",
--   "current_buffer".
-- A Telescope theme: "ivy", "dropdown", "cursor".
-- "cutie": the Qt Creator look, after Qt (pronounced "cute").
style = "default",
-- Passed to Telescope as is, for the Telescope styles. Ignored by cutie.
layout_config = nil,
cutie = {
  -- Columns of the prompt and the list. "auto" matches a sidebar window on the left, if any.
  width = 40,
  height = 15,  -- rows of the list
  preview = true,
},
```

- `style` names one style. `cursor` is both a Telescope layout and a theme; as a style it means
  the theme, which is the cursor layout with Telescope's sizes for it.
- Options given to the picker itself (`:Telescope controlk style=ivy`, or
  `require("controlk").open({ ... })`) override the config, as Telescope users expect.
  `:Telescope controlk style=cutie` opens cutie once. Telescope's own `theme=` and
  `layout_strategy=` still work and win over `style`, because they are what Telescope users
  already type.
- `config.resolve` validates `style` against the names above, and that `cutie.width` and
  `cutie.height` are positive integers. A bad value is reported the way bad prefixes are, and
  the style falls back to `default`. The styles that do not fit a locator (see the table) are
  accepted with a warning.
- The README, `doc/controlk.txt` and the defaults block in both are updated.

### Telescope styles

`default` is today's picker, unchanged: no layout is set, so whatever `telescope.setup` makes the
default applies. A layout style sets `layout_strategy` to its name. A theme style applies
`require("telescope.themes")["get_" .. name]` to the options before creating the picker.
`layout_config` goes to the picker as given. No window is hidden or shown in these styles.

Every Telescope layout and theme is a style, because Telescope users expect to choose their own.
Not every one suits a locator, whose rows are an 8-column tag, a name or path of 30 to 40 characters
and a detail, so the list needs about 60 columns. Measured 2026-11-19 by opening controlk headless
in each layout on Neovim 0.12.6 with Telescope `1e1bab7`, at 200x50 and 100x30. None failed to open.

| Style | Fit | Why |
|---|---|---|
| `default` | yes | today's picker; `horizontal` unless `telescope.setup` says otherwise |
| `horizontal` | yes | list 76x38 with the preview on the right at 200x50; no preview under 120 columns |
| `flex` | yes, suggested | `horizontal` on wide screens, `vertical` on narrow ones |
| `vertical` | yes | list 158x15 with the preview above; for tall or narrow screens |
| `bottom_pane`, `ivy` | yes, suggested | full-width pane at the bottom; the owner's `find_files` uses it |
| `center`, `dropdown` | yes, compact | list 98x15 (dropdown 78x11); the preview is too small to help on small screens |
| `cursor` | no | the theme: list 23x5, so the tag column takes a third of it, and it opens where the cursor is |
| `current_buffer` | no | covers the window you work in, preview over your code |

- `cursor` and `current_buffer` are accepted with a warning from `config.resolve` that they do
  not fit a locator.
- The README and `doc/controlk.txt` list every style, suggest `flex` and `ivy`, and name `cursor`
  and `current_buffer` as not recommended, with the reasons in this table.

### Cutie style

What the owner approved, in their sketch (prompt `c W` typed):

```
┌──────────────────────────────────────────────────────────────────────┐
│                       your code, untouched                           │
├────────────────────────────┬─────────────────────────────────────────┤
│ class  Whatever   core     │ widget.h                                │
│ class  Wing                │ 12  class Widget : public QObject {     │
│ class  Widget     ui       │ 13    Q_OBJECT                          │
├────────────────────────────┤ 14  public:                             │
│ > c W                      │ 15    void repaint();                   │
├────────────────────────────┴─────────────────────────────────────────┤
│ NORMAL  main  widget.h                               utf-8  12:5     │  status line, never covered
│ :                                                                    │  command line
└──────────────────────────────────────────────────────────────────────┘
```

- **Placement.** The prompt's bottom border sits on the last line above the status line (or
  above the command line when `laststatus` is 0). It starts at column 0. The list sits right
  above the prompt, with the same width. The preview takes the rest of the screen width, to the
  right, and spans the list and the prompt.
- **Width.** The prompt and list are `cutie.width` columns wide, borders included. The default,
  40, is Neo-tree's own default width, so it lines up with an unconfigured Neo-tree, but nothing
  is read from Neo-tree. With `width = "auto"`, cutie asks the Neovim API at open time for the
  windows of the current tab page. If the leftmost one is a split (not a float) that starts at
  column 0 and is narrower than half the screen, cutie takes its width; otherwise 40. This is
  the same for any file tree plugin, or a plain split. A floating file tree is not matched,
  because it is not part of the layout when the locator opens.
- **Height.** The list is `cutie.height` rows. If the screen is too short, the list shrinks to
  fit. If the preview would be narrower than 20 columns, or `cutie.preview` is false, there is
  no preview.
- **Order.** The best match is at the bottom of the list, right above the prompt, and the rows
  go up from there (Telescope's `sorting_strategy = "descending"`, its default). Owner,
  2026-11-19: "descending would be better, as it would be from bottom to top, closer to the
  input". The eye stays at the input, and a short list sits against the prompt instead of at the
  top of an empty box. The Telescope styles keep whatever `telescope.setup` sets.
- **Showing and hiding.** With an empty prompt only the prompt is visible. The first character
  shows the list and the preview. Deleting back to empty hides them again. The prompt stays
  where it is either way.
- **Resizing** the Neovim window recomputes the placement, as Telescope's own layouts do.
- **Keys, sorter, preview, sources and actions** are the same as in the Telescope styles.

### Prefix suggestions

Every style.

- **`?` on its own.** When the whole prompt equals the prefix of the `prefixes` source (`?` by
  default), the picker shows the prefix list as if `? ` had been typed. The prompt text is not
  changed.
- **A partial prefix.** When the prompt has no complete prefix (no prefix followed by a space)
  and is not empty, every configured prefix that starts with the prompt text is listed first,
  then the default sources' results for the same text. `c` gives `c`, `cm`, `cmo`, `ct`, then
  the buffers, files and lines that match `c`. There is no cap on the number of suggestion rows,
  because users can add prefixes.
- Suggestion rows look like the `?` list's rows, sorted by prefix, and always rank before the
  other results, whatever the fuzzy scores. With descending order (cutie, and Telescope's
  default) that puts them next to the prompt; with ascending order, at the top of the list.
- Enter on a suggestion puts `<prefix> ` in the prompt and switches to that source, as the `?`
  list does today, through the item's `prompt` field.
- Matching is literal and case-sensitive, because prefixes are.
- The logic is pure Lua in the core (the parser or the prefixes source), so a Snacks adapter
  gets it too. `picker.lua` only combines the rows.

### Acceptance

Unit specs:

- Prefix matching: `c` gives `c`, `cm`, `cmo`, `ct` in that order; `x` gives nothing; a
  complete prefix with a space gives no suggestions; a custom prefix appears.
- Width: with `"auto"`, a left split of 32 columns gives 32; a left split wider than half the
  screen, a float, or no split gives 40.
- Config: every style name is accepted; `cursor` and `current_buffer` warn; an unknown name
  warns and falls back to `default`; `cutie.width` and `cutie.height` are validated.

Integration harness, on all four pairs:

- `default` with nothing set: the same windows as today (the existing checks pass).
- `style = "ivy"`: the picker uses the `bottom_pane` strategy. `style = "vertical"`: the picker
  uses the `vertical` strategy.
- `:Telescope controlk style=cutie` opens cutie when the config says `default`.
- Cutie: with an empty prompt, the results and preview windows (and their borders) are hidden
  and the prompt is at column 0, its bottom border on the line above the status line.
- Cutie: after typing `c W`, the list and the preview are visible; the list is `cutie.width`
  wide; no cutie window overlaps the status line or the command line.
- Cutie: back to an empty prompt, the list and the preview are hidden again.
- `?` with no space lists the prefixes.
- `c` with no space shows the four suggestion rows first, then rows from the default sources.
- Enter on the `cm` suggestion leaves `cm ` in the prompt with the picker open.

By hand, by the owner, in their own config with Neo-tree: open cutie, type, pick, Esc, resize.

## Left to the builder

- The layout function's exact code, and whether it is a registered Telescope
  `layout_strategy`, a `get_window_options` function, or a `create_layout`.
- How to reach the border windows to hide them on each Telescope version.
- How suggestion rows are kept on top with the sorter pass-through.
- The text sketch above is the agreed look; borders and titles follow Telescope's defaults.

## Calls made by the designer, for the owner to check

- Option names (`style`, `layout_config`, `cutie`) and defaults (`default`, width 40, height 15).
- `cutie.width = "auto"`: what counts as a sidebar (the leftmost split, from column 0, narrower
  than half the screen), and 40 as the default rather than `"auto"`.
- `cursor` as a style means the theme, not the bare layout.
- Telescope's own `theme=` and `layout_strategy=` on the command win over `style`.
- The list has a fixed height when shown; it does not grow and shrink with the number of rows.
- No preview when it would be narrower than 20 columns.
- The cutie prompt keeps Telescope's prompt title, "Locator".
- `?` on its own shows the list without rewriting the prompt to `? `.
- Matching suggestions is case-sensitive.
- `style` can be given per call (`:Telescope controlk style=cutie`).
