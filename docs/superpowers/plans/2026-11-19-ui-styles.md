# Picker styles and prefix suggestions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `style` option (every Telescope layout and theme, `default`, and the Qt Creator-like
`cutie`), plus prefix suggestions: `?` alone lists the prefixes, and a partly typed prefix lists
the prefixes it could become, ranked before the usual results.

**Architecture:** The pure parts live in the Telescope-free core: style names and validation in
`config.lua`, the `?`-alone rule in `parse.lua`, suggestion rows in `sources/prefixes.lua`, and
cutie's geometry in a new `lua/controlk/cutie.lua`. `picker.lua` stays the only Telescope adapter:
it maps a style to Telescope options, registers the cutie layout, hides and shows cutie's list and
preview, and ranks suggestion rows first.

**Tech Stack:** Lua, Neovim 0.10.4+, telescope.nvim (v0.1.9, v0.2.0, v0.2.2, master `1e1bab7`),
plenary busted, the integration harness in `tests/integration/run.lua`.

**Spec:** `docs/superpowers/specs/2026-11-19-ui-design.md`

## Global Constraints

- Only `picker.lua` may require `telescope.*`. Sources never know which style is active.
- Every task passes on the four CI pairs: Neovim 0.10.4 with Telescope v0.2.0 and v0.1.9, 0.11.7
  with v0.2.2, 0.12.6 with master at `1e1bab7`.
- A user who sets nothing sees today's picker, apart from the new prefix suggestion rows.
- Cutie never covers the status line or the command line.
- Nothing is read from any plugin's configuration or the user's Neovim config.
- Defaults: `style = "default"`, `layout_config = nil`, `cutie = { width = 40, height = 15,
  preview = true }`. Preview dropped below 20 columns. Cutie order is descending (best match next
  to the prompt).
- Format with the repo's `.stylua.toml` (`stylua .`); `make LUACHECK=$HOME/.luarocks/bin/luacheck
  lint` must report 0 warnings.
- Run one spec file with
  `nvim --headless -u tests/minimal_init.lua -c "lua require('plenary.test_harness').test_directory('<file>', { minimal_init = 'tests/minimal_init.lua' })"`.
  Never `PlenaryBustedFile`: it loads the owner's config instead of `tests/minimal_init.lua`.
- Commits follow the rules in CLAUDE.md: the maintainer confirms each one, and the agent never
  runs `git commit` itself.
  No trailers. Work on branch `feature/ui-design`.

## Review Focus

1. **Resizing while cutie's list is hidden.** Telescope's `VimResized` handler re-sets every window
   config. A hidden list must stay hidden, and a shown one shown (Task 6).
2. **A tiny screen.** Cutie on 30x8, or narrower than `cutie.width`, must open without an error:
   the width clamps to the screen, the list shrinks to at least one row (Task 5).
3. **A prompt that starts like a prefix but is not one,** such as `cmx` or `Widget`: no suggestion
   rows, the usual results only. A prefix set to `false` is never suggested (Task 2).
4. **`width = "auto"` with no sidebar:** one full-width window, or the leftmost split wider than
   half the screen, gives 40, not the window's width (Task 5).
5. **`?` alone when the `prefixes` source is disabled or renamed:** with `prefixes = "??"`, `?`
   alone is a normal search and `??` alone shows the list (Task 2).

**Files:**

**Interfaces:**
- Consumes: `config.resolve(...).prefix_map`.
- Produces:
  - `parse.parse(prompt, prefix_map)`: unchanged signature. New rule: when no prefix-and-space
    matches and `prefix_map[prompt] == "prefixes"`, it returns `"prefixes", "", prompt`.
  - `prefixes.matching(prompt: string, prefix_map: table) -> item[]`: one row per prefix that
    starts with `prompt` (literal, case-sensitive), sorted by prefix, excluding the `prefixes`
    source itself. Empty for `""`. Each row is shaped like a `?` row (`tag` = prefix, `text` =
    the source title, `ordinal`, `prompt` = prefix .. " ") plus `pinned = true`.
  - Item contract gains `pinned`: the row ranks before every unpinned row. (Add it, and `prompt`,
    to the item list in CLAUDE.md.)

```lua
  local function tags(rows)
    return vim.tbl_map(function(r) return r.tag end, rows)
  end

  it("lists the prefixes a partial prefix could become, in order", function()
    assert.are.same({ "c", "cm", "cmo", "ct" }, tags(prefixes.matching("c", map)))
    assert.are.same({ "cm", "cmo" }, tags(prefixes.matching("cm", map)))
  end)

  it("gives nothing for text that starts no prefix", function()
    assert.are.same({}, prefixes.matching("cmx", map))
    assert.are.same({}, prefixes.matching("Widget", map))
    assert.are.same({}, prefixes.matching("", map))
  end)

  it("marks rows pinned and fills the prompt", function()
    local row = prefixes.matching("ct", map)[1]
    assert.is_true(row.pinned)
    assert.are.equal("ct ", row.prompt)
    assert.are.equal("CTest tests", row.text)
  end)

  it("follows custom and removed prefixes, and never suggests itself", function()
    local m = config.resolve({ prefixes = { lsp_classes = "cl", cmake_tests = false,
      prefixes = "c?" } }).prefix_map
```

### Task 5: Cutie geometry in the core

**Files:**
- Create: `lua/controlk/cutie.lua`
- Test: `tests/cutie_spec.lua`

**Interfaces:**
- Produces:
  - `cutie.geometry(screen, opts) -> { prompt = box, results = box, preview = box|nil }`.
    `screen = { columns, lines, cmdheight, laststatus }`; `opts = { width: integer, height:
    integer, preview: boolean }` (width already resolved, never "auto"). A `box` is
    `{ row, col, width, height }`: 0-based screen position and size **including the border**.
  - `cutie.sidebar_width(wins, columns) -> integer|nil`. `wins` is a list of
    `{ col, width, floating }`, one per window of the tab page. It returns the width of the
    leftmost non-floating window at `col == 0` that is narrower than `columns / 2`, else nil.
  - `cutie.resolve_width(width: integer|"auto", wins, columns) -> integer`: "auto" gives
    `sidebar_width(...) or 40`; the result is clamped to `columns`.

  The layout, for 200x50 with `cmdheight = 1`, `laststatus = 2` (bottom usable row 47):
  prompt `{ row = 45, col = 0, width = 40, height = 3 }`, results
  `{ row = 28, col = 0, width = 40, height = 17 }` (15 rows plus borders), preview
  `{ row = 28, col = 40, width = 160, height = 20 }` (spans results and prompt). With
  `laststatus = 0` the bottom usable row is one lower. `opts.width` is clamped to
  `screen.columns`. When the screen is short, results shrink
  to fit above the prompt, keeping at least one row. The preview is nil when `opts.preview` is
  false or it would be narrower than 20 columns.

- [ ] **Step 1: Write the failing tests** in `tests/cutie_spec.lua`:

```lua
local cutie = require("controlk.cutie")
local opts = { width = 40, height = 15, preview = true }
local screen = { columns = 200, lines = 50, cmdheight = 1, laststatus = 2 }

it("puts the prompt bottom-left above the status line, the list above, the preview right", function()
  local g = cutie.geometry(screen, opts)
  assert.are.same({ row = 45, col = 0, width = 40, height = 3 }, g.prompt)
  assert.are.same({ row = 28, col = 0, width = 40, height = 17 }, g.results)
  assert.are.same({ row = 28, col = 40, width = 160, height = 20 }, g.preview)
end)

it("uses the status line's row when there is no status line", function()
  local g = cutie.geometry(vim.tbl_extend("force", screen, { laststatus = 0 }), opts)
  assert.are.equal(46, g.prompt.row)
end)

it("never reaches the status line or the command line", function()
  for _, s in ipairs({ screen, { columns = 100, lines = 30, cmdheight = 2, laststatus = 3 } }) do
    local g = cutie.geometry(s, opts)
    local last = s.lines - s.cmdheight - (s.laststatus > 0 and 1 or 0) - 1
    for _, box in pairs(g) do
      assert.is_true(box.row + box.height - 1 <= last)

  assert.is_nil(cutie.geometry(screen, { width = 40, height = 15, preview = false }).preview)

  assert.is_nil(cutie.sidebar_width({ { col = 0, width = 40, floating = true } }, 200))
  assert.are.equal(40, cutie.resolve_width("auto", {}, 200))
  assert.are.equal(30, cutie.resolve_width(40, {}, 30))
end)
```
